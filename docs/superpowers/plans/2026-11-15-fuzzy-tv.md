# Fuzzy TV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static website, hosted on Netlify, that always plays one music video at a time on a fixed, clock-based schedule, plus an offline script that curates the schedule file.

**Architecture:** `public/videos.json` is an ordered loop of videos with durations. The page computes what's on from the America/New_York wall clock (the loop starts at midnight ET) and drives the YouTube IFrame Player. A separate Node script (`scripts/build-playlist/`) uses Last.fm and YouTube Data API v3 to discover, filter, and order videos, then writes `videos.json`. The owner runs it locally and commits the output.

**Tech Stack:** Node 22, TypeScript, Vite (vanilla TS, no framework), Vitest, `tsx` for running scripts, YouTube IFrame Player API, YouTube Data API v3, Last.fm API, Netlify.

**Spec:** `docs/superpowers/specs/2026-11-15-fuzzy-tv-design.md`

## Global Constraints

- Static site only; no server code, no runtime API keys in the browser.
- Hosting: Netlify. Build command `npm run build`, publish dir `dist`.
- Schedule epoch: midnight **America/New_York wall clock**, daily.
- Video duration filter: `60 <= durationSeconds < 600`.
- Max 3 videos per artist; seed share ≈ 1/3; artist gap ≥ 10800s of playlist time; playlist total ≤ 86400s.
- View floor default 2000; exclude channels whose title ends with `- Topic`.
- Title deny regex (case-insensitive): `\b(full (set|album|concert|show|performance)|reaction|tutorial|lesson|interview|teaser|trailer|cover)\b|#shorts`
- Caption visible for first 8s and last 8s; drift tolerance 5s; resync check every 30s; fuzz transition ~600ms.
- Secrets live in `.env` (`YOUTUBE_API_KEY`, `LASTFM_API_KEY`), which is gitignored. Ship a `.env.example`.
- Network clients take an injected `fetch` so tests never hit the network.
- Commit after every task. Messages use conventional prefixes (`feat:`, `chore:`, `test:`).

## Review Focus

1. **DST days:** on spring-forward/fall-back days, `secondsSinceMidnightET` follows the wall clock (it jumps or repeats). It must never return a negative number or a value ≥ 86400. Test it in Task 1.
2. **Viewer in a different time zone** (e.g. a laptop set to Pacific): the schedule must still use ET, not local time. Test it in Task 1.
3. **Empty or malformed `videos.json`:** show the off-air card, never a blank screen or a thrown error. Test `loadVideos` in Task 2.
4. **A video that fails to embed** (YouTube error 2/5/100/101/150): advance to the next index, wrapping from the last video to the first. Test `fallbackIndex` in Task 2.
5. **A tiny artist pool** where the 3h gap can't be satisfied: ordering must relax the gap rather than loop forever or drop everything. Test it in Task 7.

### Task 7: Ordering (mix, cap, gap, small-artist boost, deterministic)

**Files:**
- Create: `scripts/build-playlist/order.ts`
- Test: `tests/build-playlist/order.test.ts`

**Interfaces:**
- Consumes: `Video` (Task 1), `ArtistNode` (Task 5), `CurationConfig`.
- Produces: `buildOrder(candidates: Array<Video & { listeners: number }>, cfg: CurationConfig): Video[]`. The output has no `listeners` field.

Algorithm (the tests don't fully determine it, so it's spelled out here):
```
rng = mulberry32(cfg.shuffleSeed)
group candidates by normalize(artist); per artist keep the top maxVideosPerArtist by views (ties: id asc), shuffled with rng
weight(artist) = 1 / log10(listeners + 10)
clock = 0; lastAired = Map<artist, clockSeconds>; seedCount = 0; out = []
while candidates remain and clock < maxTotalSeconds:
  wantSeed = out.length === 0 ? true : seedCount / out.length < seedShare
  pool = artists with remaining videos from the wanted source (fall back to the other source if empty)
  eligible = pool.filter(a => !lastAired.has(a) || clock - lastAired.get(a) >= artistGapSeconds)
  if eligible is empty: eligible = [the artist in pool with the oldest lastAired]   // relax the gap
  pick artist by weighted random (rng); pop its next video
  if clock + video.durationSeconds > maxTotalSeconds: drop it and continue
  append; update clock, lastAired, seedCount
```

- [ ] **Step 1: Failing tests** (build fixtures with a helper `mk(artist, n, { source, listeners, dur })`):
  - **Cap:** an artist with 10 candidates → at most 3 in the output.
  - **Gap:** 20 artists × 3 videos of 300s → for every artist, consecutive airings are ≥ 10800s apart in cumulative time.
  - **Mix:** 30 seed artists + 60 discovered, 1 video each → the seed fraction of the output is within 0.25–0.42.
  - **Boost:** with seedShare 0, a 100-listener artist and a 5,000,000-listener artist, 1 video each, many runs with different `shuffleSeed`s → the small artist comes first more often than the big one.
  - **Deterministic:** the same input + seed → identical output; a different seed → a different order.
  - **24h cap:** 400 videos of 300s → total ≤ 86400.
  - **Tiny pool (Review Focus #5):** 1 artist × 3 videos → returns all 3 (gap relaxed) and terminates.

5. Album: `cached('album:'+artist+'|'+title, () => lastfm.album(artist, title))`, only for videos that survive `buildOrder`.
6. `buildOrder` → `Playlist { generatedAt: now.toISOString(), totalSeconds, videos }`.
7. Report lines: artists found (seed/discovered), artists with no channel, candidates, rejections by reason, final count, total hours, and seed share.
